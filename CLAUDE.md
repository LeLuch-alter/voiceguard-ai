# VoiceGuard AI

ИИ-оператор (чат-ассистент) для коммерческих компаний. Клиент открывает страницу, попадает
сразу в чат и общается с ИИ, который рассказывает об услугах/ценах и принимает заявки
(имя + телефон). Проект задуман как универсальный, настраиваемый под любую компанию.

## Цель и видение

Название = три опоры проекта: **Voice** (голос) + **Guard** (защита) + **AI** (оператор).

1. **Снижает, но не обнуляет затраты на персонал** — рутину берёт ИИ, сложное передаётся
   человеку (эскалация). Человек остаётся в контуре.
2. **Ровное и удобное общение** — единый вежливый тон, 24/7, на языке клиента.
3. **Полная защищённость** общения — и для компании, и для клиента (приватность переписки
   и звонков).
4. **Голос на первом месте** — основной акцент на голосовом общении, а не только тексте.

Подробный поэтапный план — в [ROADMAP.md](ROADMAP.md).

## Стек и архитектура

Проект максимально простой — без сборки и фреймворков.

- **Фронтенд:** один файл `index.html` — вся разметка, стили и JS внутри (vanilla JS).
  Без npm, без build-шага.
- **Бэкенд:** serverless-функция `api/chat.js` (формат Vercel Functions, ESM).
  Принимает `POST /api/chat`, проксирует запрос в **GROQ API** (модель `openai/gpt-oss-120b`)
  и возвращает ответ ассистента.
- **Хостинг:** Vercel (статика + serverless-функция в `api/`).
- **LLM:** GROQ (OpenAI-совместимый эндпоинт).

### Поток данных
```
браузер (index.html, fetch /api/chat)
   -> api/chat.js (добавляет system prompt + историю)
      -> GROQ API
   <- ответ ассистента
браузер рендерит и сохраняет историю в localStorage
```

## Ключевые детали реализации

- **История чата хранится локально**, в `localStorage` браузера (ключ `vg_messages`).
  Никакой базы данных и авторизации нет. «Очистить чат» стирает локальную историю.
- **Тема оформления** (`grey` / `blue` / `white`) хранится в `localStorage` (`vg_theme`),
  применяется через объект `THEMES` и функцию `applyTheme()` (инлайновые стили + динамический
  `<style id="dyn-t">`).
- **Языки** интерфейса: RU / EN / KZ — объект `LANGS` (приветствие, быстрые вопросы, подписи).
  Выбранный язык передаётся в бэкенд полем `lang` и влияет на язык ответа ИИ.
- **Заявки:** если в сообщении клиента есть телефон (регэксп в `api/chat.js`), бэкенд шлёт
  уведомление в **Telegram** (если заданы переменные окружения).
- Системный промпт ассистента задан в `api/chat.js` — нейтральный, без привязки к отрасли.
  Название компании подставляется из `COMPANY_NAME`.

## Переменные окружения (задаются в Vercel, не в коде)

| Переменная | Назначение | Обязательна |
|---|---|---|
| `GROQ_API_KEY` | Ключ GROQ API | Да |
| `COMPANY_NAME` | Название компании для промпта (по умолчанию «компании») | Нет |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота для уведомлений о заявках | Нет |
| `TELEGRAM_CHAT_ID` | ID чата/канала для уведомлений | Нет |

Секреты в репозиторий не коммитятся. Пример — в `.env.example`.

## Локальный запуск

Статику можно открыть напрямую, но `/api/chat` работает только под Vercel-окружением.
Для полноценной локальной разработки: `vercel dev` (нужны переменные окружения).

## Структура файлов

- `index.html` — весь фронтенд (UI чата, темы, языки, localStorage).
- `api/chat.js` — serverless-функция: GROQ + Telegram-уведомления.
- `logo.png` — логотип VoiceGuard AI.
- `ROADMAP.md` — план работ.

## История проекта (важный контекст)

Изначально это был демо-лендинг стоматологии «Doctor-K Dental» с примером ИИ-чата,
авторизацией и хранением истории через **Supabase**. Демо-обвязка удалена и заменена
на универсального ИИ-оператора:

- удалён лендинг стоматологии и вся «зубная» тематика -> нейтральные тексты;
- удалён Supabase (вход/регистрация и БД) -> история теперь в `localStorage`;
- чат открывается сразу, без логина;
- бренд везде — **VoiceGuard AI**.

При доработке: держать проект отраслево-нейтральным и настраиваемым; не возвращать
привязку к стоматологии; не добавлять секреты в код.
